# data-analyst — Data Sub-Agent

## Purpose

The data-analyst sub-agent processes structured data — CSV files, JSON payloads, tabular data, or pasted datasets — and returns a clear, actionable analysis in markdown. It identifies key trends, summarizes distributions, flags anomalies, and answers specific questions about the data.

It is designed for business and professional users who need to make decisions from data without spending hours in spreadsheets.

## Activation Criteria

A parent agent should delegate to data-analyst when:

- The user provides a data file or pastes structured data for review
- The user asks for a summary, trends, or insights from a dataset
- The user asks "what's unusual about this data?" or requests anomaly detection
- A report or briefing requires numerical analysis before delivery
- The user wants to compare two datasets or identify changes between periods

## Input Expected

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `data_source` | string | Yes | File path, URL, or pasted data content |
| `data_format` | string | No | One of: `csv`, `json`, `markdown-table`, `auto`. Default: `auto` |
| `analysis_focus` | string | No | One of: `summary`, `trends`, `anomalies`, `comparison`, `full`. Default: `full` |
| `question` | string | No | A specific question to answer about the data (e.g., "Which region had the highest growth?") |
| `comparison_data` | string | No | A second dataset for comparative analysis |

## Execution Steps

1. Receive and validate the `data_source` input
2. Detect or confirm the `data_format` (auto-detect if not specified)
3. Load and parse the data using the `file-reader` skill or from pasted content
4. Perform basic data quality checks: missing values, data type inconsistencies, duplicate records
5. Compute key metrics: row/column counts, value ranges, distributions, totals
6. Identify trends: directional patterns, growth/decline, seasonality if applicable
7. Run anomaly detection: values outside expected ranges, statistical outliers (> 2 standard deviations), missing required values
8. If a specific `question` was provided, answer it directly using the data
9. Generate recommendations based on findings
10. Format and return the full markdown report

## Error Handling

- **Unparseable data format:** Return: "I wasn't able to parse this data. Please confirm the format (CSV, JSON, table) and try again. If pasting data, ensure it's formatted consistently."
- **Empty dataset:** Return: "The dataset appears to be empty or contains no readable records."
- **Insufficient data for trend analysis:** Flag: "Trend analysis requires at least 3 data points over time. The current dataset has [N] — results may not be meaningful."
- **File not accessible:** Return an error with the file path and instruction to verify that the `file-reader` skill has access to the location
- **Data too large:** If the dataset exceeds processing limits, analyze a representative sample and note: "Analyzed a random sample of [N] records from the full dataset of [total]."

## Customization Notes

- **Industry-specific analysis:** Add domain context to the Execution Steps to guide anomaly thresholds (e.g., "For sales data, flag any month with >30% decline as a high-severity anomaly")
- **Output format:** If your parent agent or downstream tool expects JSON output, change `output_format` to `json` and update the Output Produced section accordingly
- **Comparison templates:** If you regularly compare the same datasets (e.g., monthly reports), create a comparison template in this section to standardize the output
- **Sensitive data:** If the data contains PII or sensitive business information, add a note to the Constraints section of your parent agent's config to prevent this sub-agent from retaining any data after the session
